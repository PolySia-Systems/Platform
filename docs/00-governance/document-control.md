# Document Control

| Field | Value |
|---|---|
| Owner | PolySia project owner |
| Maintainer | PolySia engineering |
| Status | Active |
| Version | 1.0 |
| Effective date | 2026-07-11 |
| Review trigger | Material architecture, SDK, risk, or live-readiness change |

## Fact owners

| Fact | Owner |
|---|---|
| Code, schemas, configuration | Git |
| Architecture decisions | ADRs |
| Required behavior | Requirements |
| Validation | CI and tests |
| Active work / ordinary resume | Issue or PR |
| Current operational SHA and health | Host query via the server deployment runbook |
| Major operational evidence | Dated `docs/18-ai-handoffs/` records |
| Human and agent views | Projections of the owners above |

## Authority order

1. `master-operating-charter.md`
2. Approved decisions and ADRs
3. Verified current code and tests
4. Current official Polymarket documentation and repositories
5. Historical project documents

The approved governance and delivery records preserve the modernization
history. Where legacy directory numbering conflicts with the charter, the
conflict is recorded in ADR-0010. Historical documents are evidence, not
current authority.

## Controlled documents

| Document | Status | Purpose |
|---|---|---|
| Master Operating Charter | Baseline | Project constitution |
| Project Charter | Active | Current bounded mission and scope |
| Naming Pack | Active | Canonical project identity |
| ADRs | Active | Material technical decisions |
| Registers | Active | Assumptions, decisions, risks, issues, and debt |
| Immutable Baseline Audit | Accepted | Verified migration baseline |
| Legacy phase documents | Archived | Historical evidence only |

Changes to controlled documents require a reviewed commit. Facts generated by
tests or tooling must include a review date and must not be copied forward as
timeless claims.
